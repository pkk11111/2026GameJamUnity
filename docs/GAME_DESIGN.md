# GROWL AGAIN 游戏设计文档

版本：V3 整合稿（同步规范12/G32–G41与Soap接入边界） · 2026-10-01
目标平台：Windows · 引擎：Unity 6.2（6000.2.9f1）· 类型：横版 2D 探索与构筑取舍

本文整合原设计文档及后续对话，以最新明确答复为准，面向全体成员说明游戏体验与规则。它不是已经完成的游戏功能清单，也不是全部规则已冻结的声明。

开发规则、限制、技术栈和公共接口的唯一执行入口为仓库根目录 [AGENTS.md](../AGENTS.md)。本文是其玩法的阅读版；更新已确认玩法时必须同步两者，发现冲突应交由总控处理，不能让不同成员各选一种解释。个人工作进度记录在 handoff，不写入另一套玩法规范。

## 1 游戏定位

玩家控制一只需要穿越多层空间的小狗，在获得能力、付出代价、失去能力和重新获得能力之间寻找通路，最终击败出口前的精英并离开。原案采用地狱探索、回到人类世界的叙事方向；具体故事台词、演出与最终美术尚未冻结。

核心体验是“得到什么，以及愿意舍弃什么”。能力并非只会越来越多：同一把剑可能被保留却暂时无法使用，冲刺可能为了回溯而失去，玩家也可以承担永久负面来保住自己的构筑。Regrowth 通过失去之后的再次获得和适应体现。

单局目标为 6–10 分钟。用户担任总控，其他程序人数尚未确定、不超过 5 人，替代此前固定四人的排班假设。团队主要使用 Codex 协助制作，Unity、代码和编辑器操作经验较少。此前约 38 小时是制作窗口估计，不是本文件开始时的新倒计时。采用最小可测试功能任务池，按实际人数领取，不固定个人长期板块。

### 需要保留的体验

- 获得与舍弃能力构成主循环，而非仅有加点成长。
- 固定地图的多层探索；当前暂定三层，可缩小每层面积。
- 传送与回溯需要支付代价，取消不收费，没有免费应急兜底。
- 保留三选一的取舍；战斗、敌人 AI、动画和地图复杂度可以简化。
- 基础四足移动、跳跃、咬击足以完成必要路线和战斗，不能因失去冲刺或二段跳而把主线永久锁死。

## 2 首版范围

| 范围 | 首版要求 |
|---|---|
| 基础玩家 | 移动、基础跳跃、四足咬击、受伤、死亡 |
| 可保留奖励 | 二段跳、冲刺、站立、剑，共四种，不重复、不升级 |
| 即时奖励 | 回血、生命上限或攻击等增益方向；最终池与数值待确认 |
| 付费选择 | 舍弃保留项或承担负面效果，随机三选一 |
| 探索 | 同地图暂定三层、付费往返、开关与门、宝箱 |
| 终点 | 第三层出口前精英；先击败，再由存活玩家到达出口 |
| 交付 | Windows 可执行版本；音频通过独立 Wwise 适配器接入 |

喷火、主动冷却盾、长枪仅预留身份和接口，不承诺首版可获得或可使用。没有独立武器槽、背包或耐久系统；不增加程序地图、跨局成长、跨启动存档或复杂 Boss 多阶段。普通敌人种类、攻击方式、精英招式和素材数量仍需收束。

## 3 一局游戏的流程

1. 玩家满血、四足开局，仅有基础移动、跳跃与咬击；没有初始冲刺或构筑项。
2. 探索平台、避开陷阱和敌人，遇到宝箱时从三张奖励中选择一张，也可以取消。
3. 得到保留项后构筑与攻击权限可能改变；即时增益直接结算到状态。
4. 遇到付费传送门时，从三张代价中选择一张，或取消继续当前路线。
5. 支付成功且存活才传送；持续探索、回溯、获得和舍弃。
6. 击败第三层终点前精英，存活到达出口后胜利。生命归零立即进入 Dead、暂停游戏物理并锁住玩家 gameplay 输入。死亡界面/UI/按钮由其他组员制作；重开与同帧胜负仲裁仍未冻结，没有同归于尽胜利。

不在往返时重置已领取宝箱、已触发机关或死亡敌人；本局负面也不会因换层清除。死亡后新局清空本局负面；具体重开方式和暂停菜单功能尚未确认。

## 4 玩家与构筑槽

### 基础行为

四足拥有基础咬击，不能把这项攻击直接抽为舍弃代价。移动与基础跳跃始终保留。站立姿态禁用咬击，并非永久保留攻击能力的例外补偿。

移动速度、跳高、生命初始值、攻击伤害、攻击间隔和受伤保护时间尚未指定。不要把常见的 100 HP 或其他示例数值当成已批准配置。

玩家运动/落地/脚步采用2D射线检测地面，默认每0.02游戏秒扫描，输入按键仍由集中适配器读取。脚步只随实际落地移动按独立节奏播放，不能把每次扫描变成一次发音；空中、静止、顶墙、暂停和死亡不播放、不补播。当前没有脚步材质Switch Group，不要求地面材质切换；播放间隔按素材试听调整，避免密集重叠的“机枪效应”。这一轮已更新规范与任务，实际运动/脚步实现仍由后续任务完成。

### 构筑槽（Loadout）

所有可保留技能与装备共用最多 **4 项**，即用户所说的能力槽。站立是一项，剑也是一项。即时正面和负面效果不占槽，不作为可舍弃的保留项。

| 项目 | 首版状态 | 持有后的作用 |
|---|---|---|
| 二段跳 `DoubleJump` | 实现范围内 | 提供第二次跳跃；高度和重置条件待调参 |
| 冲刺 `Dash` | 实现范围内 | 提供冲刺；方向、持续时间、冷却及是否带无敌待确认 |
| 站立 `UprightForm` | 实现范围内 | 获得后立即站立，失去后立即四足 |
| 剑 `Sword` | 实现范围内 | 只有站立时可使用；四足仍可领取并保留 |
| 喷火 `FlameBreath` | 预留 | 未来可让无武器站立玩家攻击；首版没有这一功能 |
| 盾 `Shield` | 预留 | 按键开启且有冷却，只挡敌人、不挡地形；具体参数待确认 |
| 长枪 `Spear` | 预留 | 不进入首版奖励池 |

技能和装备都不重复、不升级；已拥有项从奖励抽取池排除。能力不可用不等于能力不存在，不能仅根据当前姿态过滤舍弃项。

### 姿态与武器

姿态不能主动按键切换，也不会因拿到剑自动变化。**只通过选择奖励和代价改变站立项的持有状态**；满槽替换移除站立也属于这一结算。

| 持有站立 | 持有剑 | 当前姿态 | 首版攻击权限 |
|---|---|---|---|
| 否 | 否 | 四足 | 咬击 |
| 否 | 是 | 四足 | 咬击；剑占槽但不能用 |
| 是 | 否 | 站立 | 不能攻击 |
| 是 | 是 | 站立 | 剑击；不能咬击 |

舍弃或替换站立后立即回四足，剑仍保留且占槽；重新得到站立后直接恢复使用原剑。舍弃剑才真正移除剑并释放一个槽位。即使四足时剑暂时不可用，它仍可被抽为舍弃项。

站立无武器不能攻击是玩家选择承担的风险，不能擅自补站立咬击、自动切回四足、自动给剑或免费解救。未来喷火另行实现后才提供对应攻击。是否允许暂停菜单随时整局重开，仍待确认。

## 5 宝箱与奖励

### 三选一生成

从当前合法奖励池中等概率、不重复抽取 **3 个不同条目**。不保证“技能、装备、效果各一个”。所有已持有技能和装备排除；满血回血仍可出现，玩家可以选择没有即时收益的选项。

第一次打开后卡组固定，取消不能刷新有效项。用户明确角色已持有的技能/装备不得出现在宝箱中；重新打开旧宝箱时只补已失效项，有效项保持原位置与内容。完整奖励池及不足三项的正式处理等待新规则；当前独测实现拒绝不足三项的打开，不消耗箱子，不补假条目。

### 领取与替换

- 未满 4 项：选择新保留项并通过提交验证后加入槽位。
- 已满 4 项：所有新保留项统一进入替换流程，展示全部 4 个旧项，让玩家指定替换哪一个。
- 即时增益：直接结算，不要求腾出槽位。
- 取消整个领取流程：不领取、不移除旧项、不消耗宝箱，也不刷新原三张奖励。

替换必须一次完成：先确认新项和旧项，再提交“移除旧项＋加入新项＋姿态联动＋消耗宝箱”。不能点击新卡时就预先删旧项。玩家在最终提交前仍可放弃领取并改选增益；具体返回按钮布局由 UI 设计确定。

例：玩家持有二段跳、冲刺、站立和剑；首版四种保留项都已拥有，新奖励池不会再抽出它们，只能从足够多的即时效果中形成三选一。扩展新保留项后，满槽替换流程仍适用。**合法池不足三项时的处理尚未冻结，首版奖励池必须先设计得足够满足规则。**

## 6 传送与回溯代价

传送与回溯都收费，没有免费兜底。候选由当前持有的保留项与负面效果池共同组成，从合法池等概率抽取三个不同条目，不要求每次一定包含舍弃项。

没有任何技能或装备时，从多项负面池抽取三个选项。负面池不是固定只有三个效果；方向包括扣当前血量、降低生命上限、降低玩家攻击、增加敌人生命和增加敌人攻击。

第一次打开后代价卡组固定，取消不能刷新。再次打开时，只替换已经不能执行的代价，例如已被舍弃的技能。成功传送后下一次是否重新抽组，尚待确认。下限导致负面不能继续执行时怎样过滤，也需要跟数值规则一起确认。

### 已确认公式与作用范围

| 代价 | 已确认结算 |
|---|---|
| 扣当前生命 | `扣除量 = ceil(当前生命 × 20%)`；允许致死 |
| 降低生命上限 | `扣除量 = ceil(当前生命上限 × 10%)`；降低后当前生命不高于新上限 |
| 降低玩家攻击 | 本局永久叠加；比例、取整、下限待确认 |
| 增加敌人生命 | 本局全图所有存活敌人，包含第三层精英；按原生命比例同步当前生命 |
| 增加敌人攻击 | 本局全图所有存活敌人，包含精英；增幅与叠加算法待确认 |
| 舍弃保留项 | 移除所选当前持有项，必要时立即改变姿态；暂不可用剑仍可舍弃 |

负面持续到本局结束，死亡重开清空。强化不复活已经死亡的敌人。后续若新增动态生成敌人，如何继承本局强化仍需确认。

例：当前生命 40，扣血 8，剩 32；当前生命 1，向上取整扣 1，归零失败。生命上限 100、当前生命 95，降低上限后上限为 90、当前生命压到 90。这里 100 只用于公式示例。上限为 1 再降低会产生 0，是否允许、是否过滤和下限是多少均未确认。

### 传送结算顺序

1. 打开三选一时暂停玩法，由总控管理暂停和输入锁。
2. 玩家选代价，提交前先验证目的地与合法落点。
3. 无效落点不收费；取消不收费。不存在为无效落点改成免费传送的分支。
4. 合法后确认并应用代价一次。重复点击不能重复扣费。
5. 若代价致死，玩家在原地失败，不改变位置，不播放抵达事件。
6. 若存活才移动到目的地，抵达后获得 **0.5 秒免疫**。
7. 关闭选择流程，释放锁并恢复对应运行阶段；表现动画不得再次执行业务结算。

献祭不属于敌人或陷阱伤害，不能被盾或受伤无敌抵消。抵达免疫对不同伤害类型的覆盖细节尚需统一，不能借此默认为所有地形均可穿越。

## 7 世界结构与关卡

已确认方向是同一张固定地图、多层探索，暂定三层。第三层精英直接挡在终点前，不默认增加独立 Boss 房、额外 Boss 传送门或新场景。主线和必要返程不能要求冲刺、二段跳或必须保留的站立项。

地图已在制作，交付形式已确认是独立地图场景，由总控接入运行组件。程序功能在各自测试场景开发，地图场景按制作/接线阶段交接维护权。最终场景路径和锚点由实际地图交接说明提供；这不自动确认尚未冻结的箱数或连接关系。

开关、门、宝箱和敌人状态在本局往返时保持。具体地图尺寸、每层箱数、机关控制关系、往返是否必须使用传送门仍未全部冻结。

### 待确认的最小地图方案

以下是供下一轮讨论的方案，**不是已经批准的关卡任务**：

| 层 | 建议内容 | 需要确认 |
|---|---|---|
| 第一层 | 入门移动/咬击、少量危险、开关、2 个宝箱 | 开关是否开启第二层主线门 |
| 第二层 | 一段小探索、门、2 个宝箱、回溯入口 | 第一与第二层是否双向付费连接 |
| 第三层 | 2 个宝箱、终点前精英、出口 | 第二与第三层是否双向付费；精英败后出口是否免费 |

该方案共 6 个一次性宝箱，用短路线测试获得与舍弃，不扩大平台数量。在最终地图批准前，不能把它写成已完成地图或直接分给成员照做。

需要灰盒验证：失去冲刺和二段跳之后仍能走主线和返程；舍弃站立后碰撞体变化不让玩家卡墙；传送落点不重叠障碍；精英可用基础四足操作击败。姿态是否改变碰撞体及身体尺寸尚未确认，不能据美术自行决定通行规则。

## 8 战斗、危险与胜负

四足咬击与站立剑击是首版两种玩家攻击。攻击动画、判定范围、伤害、冷却和击退待统一；动画事件与代码必须只有一个伤害触发来源，避免同一击造成两次伤害。

盾未来只挡敌人、不挡地形。陷阱已确定为持续扣血并弹开，目标是不允许无风险烧血强行穿越；伤害频率、弹开方向、受伤无敌是否影响陷阱、落坑处理尚待确认，需要实际灰盒测试。

第三层精英属于全图负面强化作用对象。精英死亡仅解锁终点条件，不能立刻胜利；存活玩家到达出口才获胜。玩家生命归零则失败，无同归于尽结局。精英与玩家同帧死亡的事件处理顺序需由总控明确，不能由两个脚本分别决定胜负。

## 9 交互、UI 与反馈

交互跨类别优先级固定为 **传送门 → 开关 → 宝箱**。同类优先选离玩家扫描中心最近的交互锚点，距离相同时按固定交互编号排序；不可用对象跳过，继续选择可用对象。输入集中由唯一适配器处理，各模块不自行读取按键。

首版信息应能让玩家理解当前生命/上限、四项构筑、姿态、暂不可用的剑和出口条件。三选一卡应明确是保留项还是即时效果；满血回血显示无即时收益；舍弃站立提示失去剑的使用权限但仍保留剑；站立奖励提示无武器时不能攻击；扣血代价显示计算结果及致死风险。警告的交互形式待确认，不能偷偷阻止已允许的致死选择。

奖励菜单有原三卡和满槽四旧项两个阶段。取消替换不能产生实际移除。传送、奖励菜单和满槽替换都暂停；同事务切替换阶段保持暂停，成功或取消后继续，不应让UI或各模块自行设置Time.timeScale。

建议采用简短文本、槽位图标和姿态视觉变化解释规则，避免长教程。此为表现建议，不增加额外任务、剧情演出或素材数量承诺。

## 10 技术与音频边界

项目使用 Unity 6.2（6000.2.9f1）、URP 2D、C#、Rigidbody2D/Physics2D、Input System、uGUI/TMP。实际包版本、目录、格式、脚本注释、独立分支、场景锁定和 handoff 要求均见 AGENTS.md；不要在此建立另一套技术标准。
