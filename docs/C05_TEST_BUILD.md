## 队友复跑C05

1. 使用Unity6000.2.9f1打开自己的项目副本，加载Assets/WhiteBox/Scenes/Level_Whitebox.unity，保存自己的必要改动。
2. 进入全新Play，先不要领取宝箱或进入挑战，执行Tools/pawgatory/C05/Run New Map Checks (Play)。
3. Console查看C05 NewMapPlayChecks汇总。驱动会临时给予部件、移动玩家、操作实际菜单/箱门并最终进入Dead，属于破坏本次测试状态的检查，不是正常玩法或完整通关。
4. 查看临时对象上的驱动或NewMapCheckLauncher.Current.Results；退出Play还原，重新Play才可复跑。临时对象带DontSave，不保存进地图。重复入口或非全新状态拒绝。
5. 普通玩家路线还需人工试玩。自动检查用直接摆位和真实交互/按钮回调验证箱门行为，不覆盖全图基础可达性、真实设备输入、最终视觉或完整支线目标。

## Windows测试构建

当前项目Build Settings原先仅启用SampleScene；C05工具在BuildPlayerOptions中显式指定Level_Whitebox，不改全局场景列表、产品设置或脚本后端。构建前要求已保存、非Play、单个目标地图、当前Windows64及已安装Windows构建支持。

| 菜单（Tools/pawgatory/C05） | 输出用途 |
|---|---|
| Build Windows Trial | 普通Development试走包；不编译C05自动测试入口，启动后人工测试 |
| Build Windows Automated Checks | 专用Development检查包；仅本次构建添加C05_PLAYER_CHECKS，启动自动检查，90秒超时，输出逐项日志后退出 |

产物在本项目Builds/C05/<UTC时间>-trial或checks-<唯一后缀>/，每次新目录不覆盖原包；该目录已被现有.gitignore忽略。目录内含exe、配套Data/DLL和C05-build-report.txt，复制测试包时复制整个目录，不只拿exe。专用检查包不能当作正常游玩或最终发行包。

C05构建处理器只在本工具构建期间，从构建的临时场景副本移除Regrowth.Tests.*组件（包括旧90 Validation驱动），不保存或改变原地图。C05运行检查源码由UNITY_EDITOR或C05_PLAYER_CHECKS条件编译，普通包没有自动启动钩子。不会通过全局define开启测试。

运行专用检查exe可以附带-logFile指定本机日志；自动化时可使用-batchmode -nographics。成功需退出码0且日志C05_PLAYER_RESULT finished=True、failed=0、passed>0；启动拒绝为2，检查失败/超时为1。无图形运行只证明该模式下的程序行为，不能证明画面或声音通过。

Unity/插件构建回调可能自动更新本机URP资源、PlayerSettings、Wwise插件导入meta、PerformanceTest临时Resources和SoundBank暂存。工具不会自动git restore或删除未知内容：构建后检查Git差异，保留成员真实改动，仅清理由本次构建产生且已核实的附带变更；不要把这些变化误作本轮玩法修改。源码/meta、手调资产及配置按正常交付保留。

## 音频同学最终封装

最终封装由音频同学负责，总控交程序基线、地图、测试入口和未完成清单。本机测试包不覆盖其Authoring工程或SoundBank来源，也不作为音频完成证据。

- 从确认的程序提交取得最新文件，保留本人音频工程与未提交素材；美术/新版T各自按已验收版本接入。对比差异后适配，不用整份旧分支公共文件覆盖当前契约。
- 沿用GameAudio → IAudioBackend → Wwise，核对现有Cue映射、初始化/Listener、所需Bank、Windows插件与运行相对路径。WwiseSettings/Authoring修改由音频维护者按其真实环境处理，本轮不改变原音频接口。
- 最终场景列表必须明确是交付游戏场景，不直接沿用当前SampleScene列表；正式版不要使用C05_PLAYER_CHECKS、自动检查包或独测场景，检查地图中没有测试驱动。选择正式构建选项前先完成整局验收，不把当前白盒例外当正式规则。
- 声音与程序分别记录：实际动作只播一次、暂停/取消/死亡时正确停止，Bank缺失可定位且不阻塞非音频玩法；最终包在另一台没有Authoring环境的Windows电脑启动并验证Bank、菜单、运动、奖励/门和已实现整局流程。
- 最终交接写实际程序提交/音频资源版本、Unity/插件版本、场景、构建配置、必要文件、目标机验证和已知问题。未完成的战斗/收费/挑战等不能因已封装而标成完成。
